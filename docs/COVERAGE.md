# Functional coverage and adaptation map

The library groups related tasks into self-contained suites. Coverage means the
method is addressed; it is not a claim that every jurisdiction, typology or operational
system has been implemented or validated.

| Suite | Upstream specialist material | Added attachment-focused depth |
| --- | --- | --- |
| Transaction monitoring | Alert triage; transaction-monitoring methodology; Simple Toolkit investigation methods | Complete activity population, baseline comparison, legitimate explanations and fixed alert review output |
| Typologies and red flags | Typology detection mapping; AML typology reference | Mechanism → observable indicator → required data → rule condition → alternative → coverage gap |
| Investigations | Case investigation; fund-flow and SAR decision-support prompts | Event/transaction distinction, chronology, hypothesis testing and evidence-limited recommendation |
| Fraud review | Fraud investigation and detection methods | Attempted/executed/recovered exposure, payment linkage and response authority boundaries |
| OSINT research | OSINT source library; adverse-media source library; Simple Toolkit evidence standard | Source independence, entity disambiguation, procedural status and negative-search limits |
| Entity due diligence | Entity risk assessment; registry and UBO OSINT; KYC methods | Fact/evidence separation, activity expectations, opaque inputs and current source applicability |
| Sanctions review | Identity resolution; sanctions screening; ownership aggregation methods | Contradictions, identifiers, jurisdiction-specific escalation and ownership/control distinctions |
| Digital-asset review | Fund-flow tracing; wallet attribution; analytics export rationalization | Chain-aware keys, transfer semantics, fees, reconciliation and attribution limits |
| Control testing | Control matrix; independent-testing workpaper; sampling methods | Control opportunities, design versus execution, sample bias, missing evidence and retest criteria |
| Data quality | Data-governance prompts; data-quality rules | Decision-specific fields, reconciliation, distinct failure dimensions and fitness restrictions |
| Monitoring tuning | Threshold-tuning methodology | Label bias, below-threshold review, segment behavior, uncertainty and workload tradeoffs |
| Regulatory change | Obligation extraction; policy gaps; exam-response methods | Instrument status, effective dates, atomic applicability and evidence for gap closure |
| Ownership analysis | UBO, corporate registry and ownership aggregation | Dated edges, economic interests versus blocking propagation, control and unresolved paths |
| Third-party risk | Vendor due diligence; correspondent and nested-risk prompts | Service scope, dependency chains, assurance limits, control reliance and exit conditions |
| New-product risk | Product approval and risk assessment prompts | Funds/data flows, control dependencies, unresolved mandatory conditions and human launch decisions |
| Trade surveillance | Trade and communications surveillance prompts | Event-time normalization, market context, manipulative-pattern alternatives and bounded escalation |

## Deliberate exclusions

Mailbox administration, calendar indexing, scheduling, agent hosting, connector setup,
automatic notifications and external record changes are excluded. So are executable
screening engines, production detection thresholds, live watchlist redistribution and
real customer fixtures. Those would change the operational nature of the library.

An adjacent suite is optional background for a separate task. A selected suite's
runtime method cannot silently depend on attaching another folder. When a case crosses
boundaries, finish a scoped record, preserve its evidence, then start the next suite
with that reviewed record as an explicit input. Do not merge judgments or multiply
scores across suites without a documented method and authorized human review.
