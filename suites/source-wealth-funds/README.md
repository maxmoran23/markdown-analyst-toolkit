# Source of Wealth and Funds Review

Reconcile wealth accumulation and particular funding sources with dated asset, income, tax, FX, and transfer evidence.

The decision is: **What wealth accumulation and proposed funding can be explained from the supplied evidence, and which provenance or entitlement gaps remain?** This suite supports a documented analytical draft for human review. It does not assign a live customer rating, approve a relationship, clear a payment, authenticate private records, or establish regulatory compliance. Its case examples are invented and its numeric conventions are teaching methods. A mathematically exact result can still rest on uncorroborated inputs.

## Manual attachment workflow

Open a new AI session and attach the files required by the stage table in 01-session-guide.md. The full workflow uses 01 through 10. A smaller Example check stage reproduces the fixture first; Analyze preserves a complete case checkpoint; Render uses that checkpoint with one chosen output template. README and 11-build-record.md are orientation material. No terminal, installation, repository connection, connector, scheduler, unattended agent, or integration is required for an end user.

Check source readability and artifact support in the actual session. If an output cannot be generated, preserve complete report text or tables and mark the format unverified. Reproduce the fictional example before relying on new calculations.

## Start with a bounded question

State the decision, review cutoff, included population, unit of analysis, permitted sources, desired artifacts, and reviewer role. Identify whether the work is an exercise or a public-source research task. Attach the selected stage files and say: “Follow the stage contract in 01. Preserve uncertainty, reproduce the relevant example checks, and keep recommendations separate from human decisions.” Do not paste sensitive case records into an unapproved environment.

Every case must preserve its evidence register, assumptions, raw accepted rows, exclusions, calculations, conclusions, alternatives, proposed actions, and tests actually performed. A saved executive summary is insufficient to resume analysis or render defensible tables.

## Build and attachment budget

The ten instructional files contain **20,297 words** and approximately **47,732 attachment tokens** (characters ÷ 4, rounded up; code included). This is content size, not build consumption. An illustrative reproduction budget is **190,928–477,320 tokens** (4–10× content; heuristic, not observed usage). Actual generation tokens and monetary cost were not captured per suite.

The seven authored method files (01–05, 09 and 10) contain **8,032 prose/table words**, excluding fenced code and the compiled field dictionary. This separates method depth from repeated renderer code and embedded fixture payloads. Their complete file size is **54,335 UTF-8 bytes**. Counts measure content, not analytical validity.

Creation sequence: scope mapping → domain methods → fixed output contracts → complete fictional example → review checks → packaged release.
